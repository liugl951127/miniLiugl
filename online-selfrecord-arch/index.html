3.4 关键设计决策

🎯 决策 1:录制方案 = "单流独立 + 客户端本地 + 云端混流"三副本

三副本冗余保证数据安全:本地(断网兜底)+ 云端单流(每方独立,可单独质检)+ 云端混流(银保监直接播放)。任一副本损坏不影响合规性。

🎯 决策 2:会话状态存储 = Redis + 定时持久化

会话状态(包括暂停点)用 Redis 实时更新,每 30s 持久化到 MySQL。支持客户跨日续做、网络中断自动恢复。

🎯 决策 3:实时质检策略 = 端云协同

客户端轻量检测(占 CPU < 5%)做"硬规则"(人脸消失、声音异常),云端 LLM 做"软规则"(话术合规、情绪异常)。违规即时拦截,无感纠偏。

🎯 决策 4:电子签名 = SM2 + 时间戳 + 笔迹

三层证据:数字证书(身份)+ SM2 签名(不可篡改)+ 笔迹图像(防代签)。CFCA 时间戳保证事后可追溯。

📊 总结

✅ 方案亮点
  • 复用率 65%:复用现有双录平台 60% 模块,大幅降低研发成本
  • 三副本冗余:本地 + 单流 + 混流,数据安全有保障
  • 端云协同质检:硬规则(端) + 软规则(云),既实时又精准
  • 四要素 KYC:活体+人脸+声纹+设备,99.99% 反欺诈
  • 断点续传:分片 + SM3 校验,弱网 24h 可恢复
  • 三阶段交付:MVP 2 月,试运行 4 月,稳态 6 月
⚠️ 重点关注
  • 客户体验:自助场景对 UX 要求极高,需成立独立 UX 小组持续打磨
  • 活体误识:建议 ≥ 2 家厂商对比,选择误识率 < 0.001% 的方案
  • 监管沟通:本方案基于 2024 银保监办法,后续政策变化需预留扩展性
  • SFU 选型:建议云厂商 SFU + 自建双路,避免单点
  • 断点续传:本地缓存容量有限,需严格控制分片大小
