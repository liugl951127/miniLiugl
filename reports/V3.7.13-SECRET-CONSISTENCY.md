# V3.7.13 gateway 和 auth secret 处理 token 一致性

## ⚠️ 关键问题: 算法不一致

**auth (签发)**: 
```java
// JwtTokenProvider.java (V3.5.5+)
private SecretKey key() {
    byte[] raw = props.getSecret().getBytes(StandardCharsets.UTF_8);
    byte[] hash = MessageDigest.getInstance("SHA-256").digest(raw);
    return Keys.hmacShaKeyFor(hash);  // 32 bytes → HS256
}

// 签发
Jwts.builder()
    .signWith(key(), Jwts.SIG.HS256)  // 显式 HS256
    .compact();
```

**gateway (验证)**: 
```java
// JwtAuthGlobalFilter.java (V3.5.5+, V3.7.13 修复前)
if (key == null) {
    key = Keys.hmacShaKeyFor(jwtSecret.getBytes(StandardCharsets.UTF_8));  // 64 bytes → HS512
}
```

## 问题分析

| 步骤 | bytes | JJWT 算法 |
|------|-------|-----------|
| auth 签发 | SHA-256(secret) = 32 bytes | HS256 (显式) |
| gateway 验证 | secret.getBytes(UTF_8) = 64 bytes | HS512 (自动) |

**算法不匹配** → 每次验证必 401 → 这就是用户报"登录成功后 `/api/v1/auth/me` 提示 token 失效"的根因

## 修复

`backend/minimax-gateway/src/main/java/com/minimax/gateway/filter/JwtAuthGlobalFilter.java` 改 key 生成:

```java
if (key == null) {
    // V3.7.13+ 跟 auth 保持一致: SHA-256 规整成 32 字节, 强制 HS256
    try {
        java.security.MessageDigest md = java.security.MessageDigest.getInstance("SHA-256");
        byte[] hash = md.digest(jwtSecret.getBytes(StandardCharsets.UTF_8));
        key = Keys.hmacShaKeyFor(hash);
    } catch (java.security.NoSuchAlgorithmException e) {
        throw new IllegalStateException("SHA-256 not available", e);
    }
}
```
