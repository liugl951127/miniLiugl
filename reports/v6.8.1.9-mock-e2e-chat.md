## 📊 SSE 协议验证 (关键)

### 5 种 type 事件

| Event | 字段 | 用途 |
|---|---|---|
| `start` | `streamId, sessionId, status` | 流开始 |
| `content` | `content, index` | 字符 (打字机) |
| `source` | `source: {title, url, score}` | RAG 引用 |
| `done` | `streamId, sessionId, totalChars` | 流结束 |
| `error` | `message` | 错误 |

### 实际流 (部分)

```
event: start
data: {"type": "start", "streamId": "...", "sessionId": 1, "status": "started"}

event: content
data: {"type": "content", "content": "我", "index": 0}

event: content
data: {"type": "content", "content": "是", "index": 1}

...

event: source
data: {"type": "source", "source": {"title": "MiniMax AI Knowledge", "url": "https://github.com/liugl951127/miniLiugl", "score": 0.95}}

event: done
data: {"type": "done", "streamId": "...", "sessionId": 1, "totalChars": 98}
```

## 📝 关键发现

### 1. 智能问答实际是 "chat 流" 不是 "ai/generate"
- 前端 `sendMessage()` → `stream.send('/sessions/{id}/messages/stream')`
- 后端 `MessageController.streamMessage` (SseEmitter)
- 不直接调 `/ai/generate`, 而是 chat 内部 gateway → ai

### 2. 流式协议正确
- 5 type 事件设计合理
- start + content*N + source + done
- 前端 `useBusinessStream` 完整支持 (含兼容老 chunk alias)

### 3. 字符级打字机
- mock: 0.02s/字
- 后端 MessageController: 50ms/字
- Vite dev / nginx / gateway 都不应阻塞
