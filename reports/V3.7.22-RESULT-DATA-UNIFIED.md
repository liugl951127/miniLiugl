# V3.7.22+ Result 包装自动剥 (统一处理)

## 问题回顾 (V3.7.21)

后端用 `Result<T>` 包装：
```json
{ "code": 0, "message": "success", "data": <T>, "timestamp": 1234 }
```

前端之前要 `res.data.data` 才能拿到业务数据，**100+ 个 view** 都可能踩坑。

## V3.7.22 解决方案

**http.js 响应拦截器自动剥**（一处解决 100 处）：

```js
http.interceptors.response.use(
  (resp) => {
    let data = resp.data
    const respTraceId = resp.headers['x-trace-id']
    
    // 1. 业务码失败 → 拒绝 (返回整个 Result, 业务可看 code/message)
    if (data && typeof data === 'object' && 'code' in data && data.code !== 0) {
      const err = new Error(data.message || 'Request failed')
      err.code = data.code
      err.result = data  // 挂载原 Result
      return Promise.reject(err)
    }
    
    // 2. 成功 → 自动剥 data
    if (data && typeof data === 'object' && 'code' in data && 'data' in data) {
      const original = data
      data = data.data  // 剥包装
      
      // 兼容双层嵌套 (mock 可能再包一层)
      if (data && typeof data === 'object' && 'code' in data && 'data' in data) {
        data = data.data
      }
      
      // 保留原 Result 引用 (业务需要时)
      if (data && typeof data === 'object') {
        data.__result = original
      }
      return data
    }
    
    // 3. 非 Result 包装 → 原样返回 (兼容 SSE/直接返的业务)
    return data
  }
)
```

## V3.7.22 清理 (userStore 改回)

```js
// V3.7.21 (兼容)
const { accessToken: at, refreshToken: rt, user } = res.data.data || res.data || {}

// V3.7.22 (http.js 自动剥, 简化)
const { accessToken: at, refreshToken: rt, user } = res.data || {}
```

3 个方法都改回 `res.data`：
- `userStore.login`
- `userStore.fetchProfile`
- `userStore.refreshAccessToken`
