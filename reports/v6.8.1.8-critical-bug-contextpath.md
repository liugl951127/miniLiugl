# V6.8.1.8 重大 Bug 修复报告 (路径双重 v1)

## 🔴 严重问题

e9354eb commit (2026-08-08) 加 `context-path: /api/v1` 到 11 个微服务:
- minimax-admin/agent/ai/analytics/chat/model/monitor/multimodal/pipeline/rag/ws
- 但所有 controller 已经用 `@RequestMapping("/api/v1/xxx")` (绝对路径)
- gateway 11 个路由用 `StripPrefix=2` (剥 /api/v1, 留 /xxx)

**结果**:
- gateway 转发 `/chat/xxx` (剥后)
- chat 服务 context-path = `/api/v1`
- Spring 接收 `/chat/xxx` (不以 /api/v1 开头)
- contextPath = "" (空), servletPath = `/chat/xxx`
- controller `@RequestMapping("/api/v1/sessions")` 不匹配
- **所有非 auth 请求应该 404**

但用户没发现因为:
1. 用户只测过 login (auth 路由, 没 context-path)
2. 用户 vite dev 没启后端
3. 历史 commit 没真跑过端到端测试

## 修复 (3 处协同)

### 修 1: 移除 11 个服务的 context-path

```diff
# backend/minimax-{admin,agent,ai,analytics,chat,model,monitor,multimodal,pipeline,rag,ws}/src/main/resources/application.yml
server:
  port: 808X
- servlet:
-   context-path: /api/v1
spring:
```

**原因**: controller 已经用绝对路径 `/api/v1/xxx`, 加 context-path 会双重.

### 修 2: 改 gateway 14 个路由 StripPrefix=2 → 0

```diff
# backend/minimax-gateway/src/main/resources/application.yml
filters:
-  - StripPrefix=2
+  - StripPrefix=0
```

**原因**: StripPrefix=2 会剥 `/api/v1`, 但 controller 期望完整路径.

### 修 3: nginx 配置无需改

nginx 行为正确:
- `location /api/v1/ai/ { proxy_pass http://ai_service; }`
- 完整转发 `/api/v1/ai/info` → `http://ai_service/api/v1/ai/info` (proxy_pass 无 URI)
- ai 服务 context-path = / (修了), servlet path = /api/v1/ai/info
- controller 匹配 ✓


## 之前 404 根因 (用户问的)

`https://ai.liugeliang.com/api/v1/ai/info` 报 404 **不只是后端没启**:
- 启了也 404 (因为 context-path + StripPrefix=2 双重错)
- 修了后才能 200 OK

## 教训

1. **架构改变要全链路测试**: e9354eb commit 只测了"网关不 500"但没测"端到端 200"
2. **历史 100+ commit 累积技术债**: 12 个路由 + 11 个服务配置 + 100+ controller 路径
3. **AI/LLM 自动 commit 高风险**: 自动化改配置可能引入隐藏 bug
4. **必须建立 e2e 自动化**: 用户本地启后端 + 跑 curl 200 才算真 OK
