# V3.7.31+ chat MessageController 统一用 sendBusiness

## 改前（V3.7.30-）

```java
// start
SseResult.send(emitter, "start", startData);  // 显式包, data 没 type 字段

// content
SseResult.send(emitter, "content", Map.of("content", word));  // 标准 5 type

// done
SseResult.sendDone(emitter);
```

**问题**：
- start 走 `SseResult.send`（不包 type），前端 useBusinessStream 收到后，data 没 type 字段，走 onContent 默认（OK 但不规范）
- content 走 `SseResult.send`（标准 5 type），但也用 sendBusiness 才对
- 3 个不同 API 调用风格不统一

## 改后（V3.7.31+）

```java
// start
SseResult.sendBusiness(emitter, "start", Map.of(
  "streamId", UUID.randomUUID().toString(),
  "sessionId", sessionId,
  "status", "started"
));  // 自动查 type=content

// content
SseResult.sendBusiness(emitter, "content", Map.of("content", word));  // 自动查 type=content

// done
SseResult.sendDone(emitter);  // 专用
```

**收益**：
- start/content 统一走 sendBusiness（业务事件）
- 自动查 type，前端 useBusinessStream 收到 data.type 字段路由
- done/error 用专用方法（语义明确）

## 前端收到数据结构

```js
// start 事件
{
  code: 0, message: "success",
  data: { event: "start", type: "content", streamId: "...", sessionId: 1, status: "started" },
  timestamp: 1722566400000
}

// content 事件
{
  code: 0, message: "success",
  data: { event: "content", type: "content", content: "你" },
  timestamp: 1722566400001
}

// done 事件
{
  code: 0, message: "success",
  data: { status: "finished" },
  timestamp: 1722566400099
}
```
