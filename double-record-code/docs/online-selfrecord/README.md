## 1. 业务架构(摘要)

### 客户旅程 8 步 · 总时长 ≤ 8 分钟

```
预约(30s) → 强KYC(60s) → 知情同意(30s) → 风险揭示(120s)
  → 产品说明(120s) → 合同确认(60s) → 电子签字(60s) → 结束确认(20s)
```

### 与线下双录 7 大差异

| 维度 | 线下双录(已完成) | 线上自助(本次) |
|------|------------------|-----------------|
| 客户经理 | 客户经理 + 客户双人在场 | 客户独立(无人) |
| 设备 | PAD(柜面 / 上门) | 客户自有手机 / H5 |
| 签字 | 现场纸质 + 高拍仪 | 电子签名 + 手写板 |
| 引导 | 客户经理口播 | AI 数字员工 + TTS |
| 实时性 | 全程同步 | 可暂停 / 续做 / 跨日 |
| 网络 | 网点专线 | WiFi/4G/5G + 弱网容错 |
| 录制 | 单流合流(本机) | 单流独立(本机+云端+混流)三副本 |

## 3. 技术架构(摘要)

### 关键设计决策

| 决策 | 方案 | 理由 |
|------|------|------|
| **录制方案** | 单流独立 + 客户端本地 + 云端混流(三副本) | 数据安全 + 银保监直接播放 |
| **会话状态** | Redis 实时 + 30s 持久化 MySQL | 跨日续做 + 中断恢复 |
| **质检策略** | 端云协同(端做硬规则 + 云做软规则) | 既实时又精准 |
| **电子签名** | SM2 + 时间戳 + 笔迹三层证据 | 不可篡改 + 防代签 |
| **KYC 四要素** | 活体 + 人脸 + 声纹 + 设备指纹 | 99.99% 反欺诈 |

### 核心能力技术选型

| 能力 | 选型 | 关键指标 |
|------|------|----------|
| 实时音视频 | WebRTC + mediasoup SFU | ≤ 500ms 延迟,40% 丢包容错 |
| 活体检测 | 商汤 / 旷视 SDK + 静默活体 | 通过率 99.5%,反欺诈 99.9% |
| 人脸比对 | 1:1 vs 身份证 / 公安库 | 误识率 < 0.001% |
| 声纹识别 | 1:1 比对(朗读固定文本) | 等错率 < 0.5% |
| ASR | 阿里云一句话识别 | 识别率 ≥ 96% |
| TTS | 阿里云语音合成 | MOS ≥ 4.5,< 300ms |
| LLM 实时质检 | Qwen-Plus + 规则引擎 | P95 < 800ms |
| 区块链 | Hyperledger Fabric 2.2 | TPS 1000+ |

- 🌐 **数据出境**:完全境内 / 无境外 CDN / 无境外 LLM

## 6. 容错架构(摘要)

### 网络容错三道防线

1. **WebRTC 自适应**:NACK + FEC + Jitter Buffer,40% 丢包可通话
2. **断点续传**:5MB 分片 + SM3 校验,断网 30min 内可恢复
3. **离线补录**:本地 IndexedDB 缓存,完全断网 24h 可补传

### 跨日续做

```
会话中 →(主动退出/网络中断)→ 暂停中(30min 内可恢复)
  → 挂起中(超过 30min)
  → 续做中(72h 内可继续,从暂停点开始)
  → 已过期(超过 72h,需重新开始)
```

### 服务降级矩阵

| 故障 | 降级策略 | 客户感知 |
|------|---------|----------|
| TTS 挂 | 预录 TTS 库 | 无感 |
| ASR 挂 | 客户点击确认 | 多 1 步 |
| LLM 挂 | 仅走规则引擎 | 无感 |
| 活体挂 | 转人工客服 | 兜底 |
| OSS 慢 | 本地缓存 | 无感 |
| Fabric 慢 | 本地存证 + 异步上链 | 无感 |
| SFU 全挂 | 降级 P2P 模式 | 录制保留 |
